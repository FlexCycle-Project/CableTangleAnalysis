# CableTangleAnalysis (minimal dataset branch)

Headless generator and analysis pipeline for the cable-tanglement dataset used
by the paper in `latex_paper/`. One process runs exactly one seed through the
full simulation and writes one self-contained result directory; the Julia
package performs the cross-seed statistics after all seeds finish.

There is no window, renderer, mouse interaction, or GL/GLFW dependency.
KymoKnot and qhull are linked directly into `cablegen`, so knot analysis is
in-process instead of one subprocess per rope piece.

## Layout

```
CMakeLists.txt                 minimal, offline build
cablegen/                      headless simulation + dataset writer
Simulation/                    PBD simulation library (no SDF/Discregrid)
PositionBasedDynamics/         Cosserat-rod / XPBD constraints
Utils/                         headers and helpers used by the libraries
Common/                        shared types
extern/eigen/                  bundled Eigen
extern/GenericParameters/      vendored, no configure-time fetch
KymoKnot-clone/                KymoKnot sources + qhull library sources
cabletangleanalysis/           Julia analysis package
scripts/run_seeds.sh           parallel one-seed-per-process driver
scripts/aggregate_dataset.jl   per-seed directories -> aggregate TSVs -> analysis
scripts/analyze_oracle.py      optional oracle analysis (Python)
latex_paper/                   separate paper repository (git-ignored)
```

## Requirements

- CMake 3.16 or newer.
- A C++17 compiler and a C99 compiler. Everything is POSIX/standard C++; no
  OpenGL, X11, GLFW, or desktop packages are needed.
- Julia 1.10 or newer for the analysis package.
- Optional: Python 3 with NumPy and Matplotlib for `analyze_oracle.py`
  (`requirements.txt`).

No network access is required: Eigen, GenericParameters, KymoKnot, and qhull
are vendored.

## Build

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
```

The executable is written to `bin/cablegen`. To run many seeds on one machine,
one process per core is the intended parallelism model; the generator itself
does not use OpenMP.

## Run one seed

```bash
bin/cablegen --seed=42 --out=results/seeds/seed_42
```

`--seed` is required and must be non-zero. The process runs, in order:

1. cable generation and settling,
2. catalog / tanglement metrics,
3. single-cut evaluation with the exhaustive one-cut oracle,
4. cuts-to-zero evaluation with the exhaustive multi-cut path oracle,
5. topology audit.

Knot detection uses the same catalog settings as the paper pipeline. Options:

```
--creep=V                 rest-state creep (default 0.02)
--creep-settle-steps=N    settle steps before evaluation (default 300)
--creep-threshold=V       creep activation threshold (default 1e-4)
--dt=V                    time step (default 0.005)
--random-trials=N         random cut trials per sample (default 10)
--ctz-max-cuts=N          cuts-to-zero cut limit (default 10)
--ctz-random-trials=N     cuts-to-zero random trials (default 20)
--ctz-oracle-max-nodes=N  exhaustive cuts-to-zero search budget (default 5000000)
--audit-steps=N           steps per audit phase (default 300)
--audit-cuts=N            audit cuts (default 3)
--audit-contact-eps=V     audit contact tolerance (default 1e-4)
--no-oracle               skip both exhaustive oracles
--no-audit                skip the topology audit
--audit-trace             write topology_audit_trace.tsv
```

Exit status is non-zero if any stage fails. `meta.tsv` is written last and
records the complete configuration and `status=complete|failed`.

## Per-seed output

Every seed owns a directory (no shared append-only files):

```
seed_42/
  meta.tsv                        configuration, version, timestamps, status
  catalog.tsv                     settled cable metrics and knot type
  cut_eval.tsv                    heuristic/random/curvature cuts + oracle
  cut_eval_stage_metrics.tsv      per-stage metrics during cut evaluation
  cuts_to_zero.tsv                iterative cuts until unknotted + exhaustive oracle
  cuts_to_zero_stage_metrics.tsv  per-stage metrics for cuts-to-zero
  topology_audit_seeds.tsv        per-phase audit summary
  topology_audit_events.tsv       audit violations/contacts
  topology_audit_summary.txt      per-seed audit summary
  topology_audit_trace.tsv        optional, only with --audit-trace
  seed_bank.txt                   knot types observed for this seed
  run.log                         written by run_seeds.sh (stdout/stderr)
```

The five core tables (`catalog.tsv`, `cut_eval.tsv`, `cuts_to_zero.tsv`, and
the two stage-metrics files) are always required. Audit tables are optional
when `--no-audit` is used.

Version 0.3.0 appends `oracle_cuts`, `oracle_resolved`, `oracle_exhaustive`,
`oracle_nodes`, and `oracle_sequence` to `cuts_to_zero.tsv`, plus `oracle`
rows to the cuts-to-zero stage metrics. Datasets generated by 0.2.0 lack these
columns and cannot be mixed with 0.3.0 runs in one aggregate.

Two runs of the same seed with the same binary produce identical tables. The
generator fixes every random source explicitly:

- cable generation and cut-target sampling use `std::mt19937` through the
  adapters in `cablegen/DeterministicRandom.h`, not implementation-defined
  `std::uniform_*` distributions;
- there is no `std::random_device` fallback;
- KymoKnot's PRNG is seeded from the simulation seed, and qhull runs with a
  fixed joggle seed (`QR1`);
- the build disables floating-point contraction (`-ffp-contract=off`) and
  Eigen vectorization, so x86-64 and aarch64 use the same arithmetic order.

Outputs from older builds are not comparable: the legacy catalog used
`std::random_device` and library distributions, and the GUI-era build enabled
OpenMP. Different standard-library or libm versions can still differ in the
last bits; use the same toolchain for a dataset that must be bit-identical.

## Parallel dataset generation

`scripts/run_seeds.sh` owns seed iteration and scheduling. The generator only
ever sees one seed.

```bash
# seeds 1..10000, 92 concurrent processes
scripts/run_seeds.sh --seeds 1:10000 --jobs 92 --out results/seeds

# a seed list (one integer per line, # comments allowed)
scripts/run_seeds.sh --seeds seeds.txt --jobs 92 --out results/seeds

# pass generator options after --
scripts/run_seeds.sh --seeds 1:10000 --jobs 92 --out results/seeds -- --creep=0.03
```

The driver:

- sets `OMP_NUM_THREADS=1` and runs one `bin/cablegen` process per seed,
- skips a seed whose `meta.tsv` already says `status complete`,
- writes per-seed `run.log`, a `failed_seeds.txt`, and a `summary.tsv`,
- exits non-zero if any seed failed.

Use `--force` to re-run completed seeds. Each `cablegen` process peaks around
150–250 MB, so size `--jobs` to fit the machine's memory (92 jobs is roughly
15–25 GB). A pathological seed can still kill its own process; the driver
records it and continues with the remaining seeds.

KymoKnot localization occasionally asks qhull to close a 2–3 bead subchain.
Those subchains are now returned as plain short arcs, which the knot
identifier treats as the unknot, instead of calling `abort()`.

## Aggregate and run the Julia analysis

The per-seed process writes raw data only. Cross-seed PCA, correlations,
paired tests, plots, and tables need the whole population, so they run once
after all seeds are complete:

```bash
julia --project=cabletangleanalysis \
    scripts/aggregate_dataset.jl results/seeds aggregate
```

This step:

1. discovers `seed_*/` directories,
2. checks that every seed's `meta.tsv` reports the same configuration and is
   `complete` (incomplete seeds are skipped with a warning),
3. validates that all table headers match and concatenates the tables into
   `results/seeds/aggregate/`,
4. invokes `cabletangleanalysis/scripts/run_dataset.jl` on the aggregate.

Analysis output goes to `results/seeds/analysis_julia/aggregate/`
(`figures/`, `tables/`, `data/`, `complexity/`). Add `--no-analysis` to stop
after writing the aggregate TSVs.

After the Julia analysis, the optional oracle analysis can consume the
aggregate `cut_eval_with_complexity.tsv`:

```bash
python3 scripts/analyze_oracle.py \
    --dataset-root results/seeds \
    --out-dir results/seeds/oracle_analysis
```

`cabletangleanalysis/STATISTICS.md` documents the statistical methods.
